---
title: Adding a New Robot
description: How to generate ROS 2 packages from an OnShape CAD model and get a new robot running in Gazebo.
---

The command `sim gazebo create` takes a robot from OnShape and produces two ROS 2 packages. To make sure we do not hit the low OnShape API limits, requests to OnShape are routed through the [dashboard](https://github.com/TrickfireRobotics/dashboard.git) that authenticates you and caches common requests long-term.

## Getting access

You do not need a dashboard account. Access runs on a 6-digit code that rotates every day at midnight, and any team lead can read today's code off [dashboard.trickfirerobotics.com](https://dashboard.trickfirerobotics.com) → Settings.

<Steps>
    <Step>Ask a team lead for today's sim access code.</Step>
    <Step>
        Run `sim gazebo auth` and paste it in. The code is saved to
        `~/.config/trickfire/token.json`.
    </Step>
    <Step>Create the robot: `sim gazebo create <robot_name> <onshape_url>`.</Step>
</Steps>

The code stops working when it rotates, so if you come back the next day, ask for a fresh one and run `sim gazebo auth` again. If you do have a dashboard account, a personal API key from Settings → CLI access works the same way and does not expire.

<Callout type="info">
    Only `sim gazebo create` and `sim gazebo update` need a code. Running an existing robot works
    with no credentials at all, since the generated packages are committed to this repo.
</Callout>

## Flags

| Flag                   | Description                                             |
| ---------------------- | ------------------------------------------------------- |
| `--attach-to-world`    | Fix `base_link` to the Gazebo world (stationary robots) |
| `--no-attach-to-world` | Explicitly skip - for mobile robots                     |
| `--no-reduce`          | Skip STL mesh decimation (larger files, higher detail)  |
| `--output-dir <path>`  | Write packages somewhere other than `gazebo/`           |

## Updating an existing robot

When the OnShape CAD changes, pull in the new geometry without touching your bringup config using this command:

```bash
sim gazebo update arm
```

This replaces only `arm_description/urdf/arm.urdf` and `arm_description/meshes/`. Everything else, your control xacro edits, launch file, controller YAML, RViz config is left untouched.

## Troubleshooting

<Accordions>
    <Accordion title="There are joints missing">
        Joints must be defined as mates in the OnShape assembly. Check the OnShape model if joints
        don't appear in the generated controller YAML.
    </Accordion>
    <Accordion title="There are URDF errors after generation">
        `sim gazebo create` post-processes the raw OnShape URDF (mesh paths, control xacro
        generation, indentation). Check the OnShape assembly for unexpected geometry or joint
        definitions if the generated URDF still looks wrong afterwards.
    </Accordion>
    <Accordion title="'sim gazebo auth' rejects the code">
        Codes rotate at midnight, so yesterday's code will not work. Ask a lead to re-read the
        current one off the dashboard. After several wrong codes the dashboard rate limits your
        network for an hour.
    </Accordion>
    <Accordion title="'sim gazebo create' fails with 'access rejected' mid-session">
        The code rotated while you were working. Run `sim gazebo auth` with today's code and
        re-run the create.
    </Accordion>
</Accordions>
